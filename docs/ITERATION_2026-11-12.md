# 第二轮补充与验收：规划可靠性、RAG 上下文及 PDF 来源

日期：2026-11-12。分支：`feature/personal-learning-coach`，基线 `1b9d3d1`，包含 11 月 11 日个性化记忆首轮改动。这是实现时的来源基线；当前交付仓库和默认分支见 [START_HERE](../START_HERE.md)。

## 已实现

### 考前排程与学习日期

- CP-SAT 和确定性降级算法共用考前日期范围，最晚安排到考试前一天，最多七天。
- 校验器检查计划范围、每条任务日期、每日容量、高负荷数量和必做任务。时间不足时明确保留冲突，不越过考试日期凑任务。
- `LEARNING_TIMEZONE` 默认 `Asia/Shanghai`。规划、考试日期输入、今日任务和概览中的学习日期使用同一规则；前端按服务端学习日期和日历日期显示，避免 UTC 日期偏移。
- 临近考试的短计划只展示实际有效天数。存在未满足约束的草案不能启用。

### 草案、档案与审批一致性

- 草案持久化保存档案签名和生成时的正式计划 ID。执行中档案或正式计划变化，旧结果不能落库；审批时再次校验。
- 档案变更会使旧草案失效；考试日期或可用时间变更会同时停用已不适用的正式计划。
- 审批、画像更新、任务完成使用数据库事务内的同一用户写锁。并发启用不同旧草案时只有一个草案能成为当前正式计划；同一已启用计划重复请求保持幂等。
- 新迁移 `0008_plan_approval_guard` 增加每个用户最多一条 approved 计划的部分唯一索引。升级时若存在重复 approved 记录，按创建时间和 ID 保留最新，其余转为 superseded，任务和记录不删除。
- 已过考试日期的历史画像仍可查看；新输入日期和新规划保持未来日期校验。

### 真实工作流进度

- JSON 生成接口与 SSE 共用执行服务，实际运行 `intake → diagnose → retrieve → plan → validate`。
- 每个节点执行完成才发送事件，同时持久化轨迹；草案与终态写入成功后才发送 completed 和 plan_id。
- 失败保留已执行轨迹并标为 failed，不发送假完成。新增 `GET /api/v1/agent/runs/{id}` 供当前用户读取自身执行状态。
- 幂等键按用户隔离；相同已完成请求可重放结果，失效请求需重新生成。
- 本周计划页面消费实际 SSE 事件，更新草案并刷新当前画像容量。

此处 retrieve 仍读取内置评分参考，检索证据没有参与排程选择；不将本轮描述为 RAG 驱动计划。

### RAG 追问、关键词与上下文预算

- 对“上次/那条规则/Explain that again”等追问，结合上一问题和来源标题构造检索问题；独立新问题保持独立，不再无差别拼接旧问题。
- 历史回答只作为对话上下文，过时历史不复用，限制条数和序列化字符数；不把旧 AI 回答拼成检索依据。
- 英文停用词过滤、中文双字词片段和 BM25 式关键词排序替代按英文子串/中文单字的简单计数，继续与向量及个人关联候选融合。
- `RAG_EVIDENCE_CHARS=18000` 限制序列化证据总字符数，`RAG_SOURCE_CHARS=5000` 限制单来源正文。截取原文中的连续片段；返回引用与实际进入模型的来源一致。通用助手和作文追问均接入。
- 返回 `retrieval_query` 与 `evidence_chars` 便于审查。字符预算不是供应商 token 计费测量，也不代替真实检索质量评测。

### PDF 解析、来源查看与收藏

- 文本型 PDF 使用现有环境的 pypdf 逐页提取，分块保留 1 起始的真实页码；空白页不导致后续页码错位。
- 加密 PDF 和无法提取文字的扫描件返回明确错误。OCR 仍为候选，不伪造提取结果。
- 失败时回滚片段替换，再保存失败状态，避免半套索引被当作完成。
- 新增受当前用户权限保护的 `GET /knowledge/documents/{id}/chunks` 与 `/file`，支持页码、片段分页和原文件读取；兼容 UUID 上传文件和项目既有公共资料标识。
- 资料页支持查看文字、按页选择、打开原文件和收藏片段。内部引用带页码参数，外部 PDF 引用带 #page 跳转。
- 收藏保留所选 chunk_id，避免 PDF 多页相同句子被错误记录到第一页。原始快照和来源位置保持可核对。
