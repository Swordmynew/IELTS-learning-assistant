## Failures found and corrected

Early live attempts exposed native FastEmbed `numpy.float32` vectors failing JSON persistence, an otherwise usable response rejected for its supplied quarter-band aggregate, an omitted optional next exercise, and missing comparisons for earlier issues. Fixes convert vectors to Python floats, normalize the aggregate, default the optional field, and explicitly request/validate all prior issue IDs with one corrective retry. Native-vector JSON persistence has a regression check in `backend/tests/test_embeddings.py`.

The first successful cross-subject answer still called a project-authored practice explanation “官方解析”. Retrieval now supplies explicit provenance/license metadata, the instruction distinguishes practice explanations from official rubric summaries, and expanded source cards show compact origin labels. The focused follow-up attributed its source correctly. Future model calls can still make attribution or reasoning mistakes; valid source IDs alone do not establish that every claim follows from the evidence.

The sandbox blocked temporary-file access for one smoke invocation and child-process creation for one browser invocation. The same checks were rerun with the required permissions and completed; those environment failures are not counted as successful checks.

A sandboxed restart also failed while the old services remained reachable. The startup script now checks process-inspection access before changing saved IDs and waits for both child processes and HTTP readiness before reporting success. After a permitted restart, the API startup log showed a new server PID and OpenAPI exposed the newly added provenance fields; proxy authentication/dashboard and all four browser tests passed against those services.

## Limits

The live smoke uses a small fixed synthetic dataset and a single provider configuration. It does not establish score calibration, retrieval precision/recall, learning efficacy or reliability across repeated model runs. The observed revision statuses included partial improvement; score gains are not guaranteed. Personal practice evidence informs advice, while official rubric summaries provide assessment criteria.

SQLite and the local FastEmbed path were exercised. PostgreSQL deployment was not exercised here; the new personal retrieval path uses the portable vector/keyword implementation and loads candidate records into application memory, suitable for a course-sized corpus. PDF/DOCX extraction, large-corpus performance and human grading calibration remain outside this validation. Task 1 keeps its existing interface; Reading, Listening and vocabulary supply personal records without receiving a full new AI practice workspace.
