## 1. 课程依据与项目选择

已逐页读取 DSAI5205_Final_Project_Guidance.pdf（3 页）。第 1 页要求使用免训练策略实现一个可交互的 LLM 应用，展示至少一种现代 LLM 技术。RAG、MCP、Agent Skills 为技术示例，选择 RAG 即可。外部知识源属于鼓励项；没有规定知识库规模或强制 100 条样本，也明确无需大型对比实验，但需说明设计为何适合、系统为何工作正确。

第 1–2 页要求展示问题与场景、技术选择与理由、实现方式、主要功能和截图、实际收益与当前边界。报告最多 10 页（不含参考文献），含 Introduction、Method、Implementation、Demonstration、Discussion。上述要求来自课程 PDF；下面的具体模块、样本规模和验收方案是本项目建议。

本项目拟突出：基于用户真实练习错误与主动收集的碎片笔记，构建可追溯、可更新、按当前练习检索的个人记忆；用这些记忆辅助答疑、作文修改与短练习。积累记录、更新索引和检索上下文均在推理时完成，符合免训练方向。

## 2. 当前基础（已实现）

- personal_knowledge.py：自动捕获错题、历史词义错误，回填历史学习记录；同一题/词的知识条目更新到最近结果。
- coach_api.py：作文问题自动积累，并更新上一版本问题的改善状态；支持知识条目的编辑、删除和同类型合并。
- search_repository.py：公共/私人资料与个人知识联合检索，向量与关键词排名融合，支持来源类型、文档、科目过滤。
- coach_model.py：按用户、上下文和资料修订指纹隔离模型缓存；结果结构及来源 ID 校验。
- resources/personal-knowledge.tsx：现有知识列表、备注编辑、来源跳转与合并界面；尚无通用“新建碎片笔记”入口。
- 写作评分当前使用内置量表摘要，个人历史用于建议；规划 retrieve 的 evidence 未被排程函数消费。

接手时缺口：通用碎片采集、跨记录错因聚合、多次练习统计驱动的检索、记忆生命周期与个性化收益证据。首轮功能及验收状态已记录于上述实现文档；真实收益仍待真实材料验证。

## 3. 建议的数据分层

### A. 原始事件：保留发生过什么

错误事件关联 attempt/version/issue，记录原句或题目、用户答案、正确答案（存在时）、反馈来源、时间、科目及来源定位。优先关联现有作答/作文表，不重复保存整篇大文本。为每个事件设置稳定唯一标识，重复提交不重复计数。

人工笔记保存原文、可选说明、来源 URL/文档页码或手工录入标记、收集时间、标签。网页摘录和上传片段保存必要原文快照，不依赖外链永远不变。网页自动抓取、OCR、浏览器扩展留在后续阶段，先完成粘贴文本与练习内收藏。

### B. 派生记忆：将证据组织为可复用学习点

围绕标准错因键聚合：例如 grammar.countability、grammar.article、lexical.collocation、reading.paraphrase。保留所属用户、科目、关联事件 ID、首次/最近出现、独立练习次数、最近结果、改善状态，以及对应笔记/知识点链接。

原始作答、用户备注、AI 推断分开保存。AI 生成的错因标签注明来源与模型/版本，可由用户修改；自动积累无需逐条弹确认。一次错误只支持本次观察，多次独立记录才支持反复错因描述。相同事件重试不能增加错误频次。

同类条目可自动建议关联，原始证据保持可回溯；不要用自动生成摘要覆盖原始事件或用户笔记。

### C. 权威与参考资料：提供解释依据

保留资料来源、许可、适用科目、知识点、片段和页码。个人笔记和 AI 历史反馈提供学习背景；官方量表或经核实材料提供评分/规则依据。来源类型在回答与界面保持可区分。

| --- | --- | --- | --- |
| P0 | 随手记录 | 新建/编辑/删除笔记；题目、作文和答疑片段“收藏为笔记”；可选来源与标签 | 收藏后能检索到原文并打开原始位置；无来源的手工笔记明确标记 |
| P0 | 错因关联 | 统一标签；按用户聚合同类错因；笔记可关联相关错误/知识点 | 两次不同练习的相同错因连到同一主题，独立证据均可查 |
| P0 | 个性化检索 | 当前问题/作文 + 同主题历史错误 + 相关个人笔记 + 参考依据 | 相同问题、不同学习历史能检索不同个人证据，同时保持适用的公共依据 |
| P0 | 可解释回答 | 指出本次问题，引用历史实例与相关规则，提供修改建议和短练习 | 每条个人观察能追溯到真实记录；引用 ID 合法且原文支持对应表述 |
| P0 | 学习闭环 | 练习/重写结果更新记忆状态、频次和复习优先级 | 新证据进入检索；已改善问题降权；再次犯错可恢复优先级 |
| P0 | 生命周期 | 编辑后重建索引、删除后停止检索、对应缓存失效、用户隔离 | 删除/编辑后旧记忆不再用于后续检索和回答，其他用户始终不可见 |
| P1 | 观察检索过程 | 开发调试记录检索范围、候选、最终片段和选择原因 | 能说明为何返回某段个人材料；不把调试细节堆入学习页面 |
| P1 | 对话跟进 | 利用当前问题和必要历史解析“上次那种错误”等指代 | 不把整段聊天无差别塞入检索，跟进问题仍引用相应证据 |
| P1 | 页面体验 | 碎片知识、错因主题、最近积累、待复习筛选；适度显示关联证据 | 从记录到问答再到练习有直接入口，页面文字保持克制 |

## 5. 个性化检索的具体规则

1. 用户权限、资料删除状态、来源范围是硬过滤，先于排序。
2. 用当前问题、练习主题/原句、科目和错因标签建立检索上下文；用户画像提供目标与解释深度。
3. 保留现有向量+关键词候选，加入同错因、相近练习和关联笔记候选；去重后限制单一来源占比及总上下文长度。
4. 排序主要依据问题相关性；当前任务关联、近期独立错误频次、未解决状态、复习到期作为调节因素。权重需用样例验证，不预先宣称最优。
5. 保留必要公共依据，同时选少量最相关的个人证据。历史问题与当前问题不相关时不强行插入。
6. 已改善状态可降低提醒频率，历史仍保留；一次答对不直接宣称掌握。
7. 将选中的证据明确传给生成器，回答只按证据强度描述个人情况；没有历史则正常解释并说明暂无对应个人实例。
8. 上传文档、摘录和笔记作为待引用资料，不作为改变系统行为的指令；用对抗性片段做回归。

当前实现的资料 fingerprint 随全库增长成本上升。后续用用户/知识库修订计数和可追踪索引版本替代反复全量扫描，模型调用和文档摄入失败可重试。

## 6. 一个可展示的闭环（示例，非实验结果）

1. 用户在独立练习中写出 many information，错误事件关联原句。
2. 用户随手保存笔记：information 为不可数名词；记录来源和个人例句。
3. 后续作文再次出现相同问题，聚合为“不可数名词数量表达”，关联两次事件与笔记。
4. 用户问“这段作文我应该先改哪里？”系统检索当前原句、相关历史证据及规则解释，给出相应修改，并附两道针对性小练习。
5. 用户完成新练习或修改作文，结果写回事件与派生记忆；提示优先级随新证据更新。

另一个用户没有该历史时，回答不应声称他反复出现这个问题。两个账号对同一句查询的不同证据结果，是课程中易于说明的个性化演示。

## 7. 课程演示和质量证据

建议准备 20–30 条人工核对的课程演示/功能样例，覆盖：中文/英文、同问不同用户、冷启动、重复错因、已改善、无相关资料、编辑/删除、资料冲突、跨用户隔离及材料中包含指令文字。合成记录必须标明为测试夹具，不算真实用户研究结果。

用同一批问题检查两个配置：公共资料 RAG，以及公共资料+个人错误/笔记的 RAG。可小规模人工核对相关个人证据是否进入 Top-k、引用是否支持回答、个人事实是否正确、建议是否针对当前问题、无证据时是否正确处理，以及响应耗时。结果据实填写，不预先填准确率。

20–30 是本方案建议的课程演示起点。既有 docs/EVALUATION.md 的至少 100 条人工复核、Recall@5 等发布门槛保持原样；小样本演示不代表这些门槛已达到。没有必要为了课程额外同时建设 MCP、Agent Skills 或大型知识图谱。

最终演示准备一个真实模型端到端案例，附检索片段和回答截图；离线固定示例作为备用。报告写清数据如何进入、如何检索、如何影响回答、如何更新，以及当前仍待真实样本验收的部分。

## 8. 建议实施顺序

第一轮：碎片笔记创建/收藏 + 错因结构与关联 + 基于当前任务的个人检索 + 来源展示。
第二轮：新作答回写状态 + 记忆编辑/删除/缓存一致性 + 双账号与冷启动回归。
第三轮：真实模型案例、人工小样本检查、截图与报告方法/演示部分。
后续候选：PDF/OCR、自动网页收集、数据库规模优化、检索增强计划；材料或外部资源到位后再加入。

代码和数据迁移在本分支内实施，使用独立数据库验证；保持现有功能和测试，不连接旧目录实际数据库。首轮已新增 API 和界面，复用现有 CoachRecord 表；最新状态以实现文档为准。
